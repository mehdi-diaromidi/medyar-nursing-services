### ۱.۱ مسیریابی وردپرسی — رفتار فعلی

- هر برگه یک قالب دارد و زیرصفحه با `?mns_page=` انتخاب می‌شود؛ ناوبری **بارگذاری کامل صفحه** است، پس دکمهٔ برگشت مرورگر و deep link ذاتاً کار می‌کنند.
- `mns_panel` تکراری است: پنل از قالب برگه معلوم است و پارامتر فقط در URL می‌آید.
- **slug نامعتبر بی‌صدا به داشبورد برمی‌گردد** (`current_page()`)؛ صفحهٔ «پیدا نشد» وجود ندارد.
- **`document.title` برای همهٔ زیرصفحه‌ها یکی است** (عنوان برگهٔ وردپرس، مثلاً «پنل بیمار پرستاری»).
- `order-view` پارامتر `mns_order` را نادیده می‌گیرد؛ همیشه یک fixture ثابت.
- در `order-view` هیچ آیتم منو active نیست (باید «سفارش‌ها» active بماند).
- **هیچ کنترل دسترسی وجود ندارد:** پنل بیمار/پرستار برای کاربر لاگین‌نکرده هم رندر می‌شود (بریف: سفارش فقط با حساب). نقش پرستار هم چک نمی‌شود.
- صفحهٔ خدمت `?mns_service=` را فقط برای سوئیچ به view می‌خواند؛ **هر ۶ خدمت محتوای «سرم‌تراپی» را نشان می‌دهند** (یک fixture ثابت).

## ۲. سیستم طراحی موجود

### ۲.۱ توکن‌های تم (`dr-plus`، منبع اصلی)

| گروه | توکن‌ها |
| --- | --- |
| رنگ برند | `--primary-100` (+ `-20`، `-36`، `-50`)، `--primary-200`، `--secondary-100/200` |
| متن | `--text-main`، `--text-100…600`، `--heading-100/200` |
| خاکستری | `--gray-100` (`#F7F7F7`)، `--gray-200`، `--gray-300`، `--gray-400` |
| سطح | `--body`، `--general-bg` |
| شعاع | `--global-border-radius-1` (۲۴)، `--global-border-radius-2` (۱۶) |
| فونت | `--main-font: "IRANYekanXFANum"`، `--secondary-font: "AnjomanFANum"` |

نکته: در `style.min.css` مقدار پیش‌فرض `--primary-100` فیروزه‌ای (`#1DBAB5`) است و روی سایت با کیت Elementor به آبی مدیار بازنویسی می‌شود. پلاگین همیشه باید از `var(--primary-100)` بخواند، نه fallback.
نکته: فونت `…FANum` ارقام لاتین را **با گلیف فارسی** نمایش می‌دهد؛ این نمایش را درست می‌کند ولی دادهٔ متنی، کپی و صفحه‌خوان همچنان لاتین است. پس فرمت عدد فارسی باید در لایهٔ داده/نمایش هم انجام شود.

- فاصله: `--mns-space-1…8` = ۴/۸/۱۲/۱۶/۲۴/۳۲/۴۰/۴۸.
- کنترل: `--mns-field-min-h` (۵۰)، `--mns-touch-min` (۴۴)، `--mns-focus-ring`، `--mns-sidebar-width`، `--mns-sticky-top`.

### ۳.۱ الگوهای تکراری/ناهماهنگ

1. **سه الگوی مختلف برای «فهرست سفارش»:** جدول expandable (بیمار)، جدول ساده (داشبورد بیمار و پرستار)، کارت (سفارش‌های پرستار).

3. **فرم‌های mock** همه با `data-mns-mock` و یک notice بالای فرم؛ بعد از «موفقیت» فرم سر جایش می‌ماند و هیچ صفحهٔ نتیجه‌ای نیست.
4. **میکروکپی پراکنده:** متن‌ها در PHP (`esc_html__`) + **۴۹ رشتهٔ فارسی hard-code در JS** که ترجمه‌پذیر نیست.
5. **شمارهٔ پشتیبانی** فقط در `service.php` و به‌صورت hard-code (`02188607015`)؛ پنل‌ها دکمهٔ تماس ندارند.
6. **قالب عضویت از wrapper کاتالوگ** (`.mns-catalog`) استفاده می‌کند؛ کاتالوگ و عضویت شِل یا PageHeader مشترک ندارند.
7. **لینک‌های خروجی** (پنل مدیار، کیف پول) هیچ نشانهٔ external ندارند.
8. **تاریخ و عدد در fixture متن آماده‌اند** (`'۱۴۰۳/۰۸/۱۲'`، `'۱٬۲۵۰٬۰۰۰ تومان'`)؛ موبایل و کد پیگیری لاتین‌اند. ابزار تاریخ انسانی («امروز/فردا») وجود ندارد.
9. **ناسازگاری قرارداد داده بین fixtureها:** بیمار در `new_order` (`age`، `gender`) با `patients_list` (`phone`، بدون سن/جنس) و `dashboard` هم‌شکل نیست؛ سفارش در `orders`، `dashboard` و `order_view` سه شکل دارد.

## ۴. مشکلات UX هر صفحه

شدت: 🔴 بحرانی · 🟠 مهم · 🟡 جزئی

### کاتالوگ عمومی

**آرشیو خدمات**
1. 🟠 فقط یک گرید کارت؛ بلوک‌های «نمی‌دانید کدام خدمت؟»، «چطور کار می‌کند»، نظرات مثبت و FAQ نیست.
2. 🟠 کارت‌ها آیکن ندارند؛ اسکن بصری ۶ دسته کند است.
3. 🟡 حالت خالی یک notice قرمز «خطا» است (empty ≠ error).
4. 🟡 همهٔ متن کارت با style درون‌خطی.

**صفحهٔ خدمت**
1. 🔴 هر ۶ خدمت یک محتوا (سرم‌تراپی) نشان می‌دهند؛ تمپلیت داده‌محور نیست.
2. 🔴 CTA «ثبت درخواست» خدمت را به ویزارد پاس نمی‌دهد (کاربر دوباره انتخاب می‌کند).
3. 🟠 بخش‌های بریف («برای چه کسانی»، «شامل چه»، «قبل از سفارش آماده کنید»، کارت‌های عوامل هزینه، FAQ، خدمات مرتبط) نیست.
4. 🟠 CTA روی موبایل چسبان نیست؛ شمارهٔ پشتیبانی لاتین و بدون متن «تماس با پشتیبانی مدیار».
5. 🟡 متن نظر شامل «بدون ذکر نام» داخل نقل‌قول است (میکروکپی اشتباه).

### پنل بیمار

**قالب کلی**
1. 🔴 بدون کنترل لاگین/نقش.
2. 🟠 bottom nav ندارد؛ منوی ۱۰ آیتمی در drawer پنهان با زبانهٔ لبه‌ای.
3. 🟠 badge شمارنده (فاکتور پرداخت‌نشده) ندارد؛ `document.title` یکسان؛ slug نامعتبر → داشبورد بی‌صدا.
4. 🟡 «پنل مدیار» بدون نشانهٔ external؛ موبایل در هدر لاتین.

**داشبورد**
1. 🟠 ردیف ۳ متریک بی‌اقدام بالای صفحه (anti-pattern).
2. 🟠 کارت «اقدام اصلی» وضعیت‌محور (فاکتور ← سفارش فعال ← پرسشنامه ← دعوت) وجود ندارد.
3. 🟠 ثبت سریع با ۶ دسته / «تکرار آخرین خدمت»، پیشرفت مهرها و میانبر بیماران نیست.
4. 🟡 جدول «آخرین سفارش‌ها» روی موبایل اسکرول افقی؛ حالت کاربر جدید و تخفیف سفارش اول نیست.

**ثبت سفارش**
1. 🟠 ترتیب مراحل با بریف فرق دارد (خدمت و جنسیت پرستار در مرحلهٔ ۳؛ بریف: خدمت در ۱، جنسیت در ۲).
2. 🟠 تاریخ ورودی متنی آزاد است؛ چیپ ۷ روز آینده و بازه‌های ساعت نیست؛ آدرس‌های قبلی نیست.
3. 🔴 خروجی‌های «موفق / پرستار موجود نیست / خطای شبکه» صفحه ندارند؛ فقط notice درون فرم. پیش‌نویس حفظ نمی‌شود.
4. 🟠 «بیمار جدید» فیلدها را درون مرحله باز می‌کند (به‌جای sheet)؛ مرور نهایی لینک «ویرایش» per بخش ندارد؛ خلاصهٔ چسبان دسکتاپ و StickyActionBar موبایل ندارد.
5. 🟡 خطاها فقط در notice بالای فرم؛ فیلد خطادار علامت نمی‌خورد و فوکوس نمی‌گیرد.

**سفارش‌های من**
1. 🟠 جدول expandable روی موبایل اسکرول افقی؛ تب فعال/گذشته/لغوشده نیست.
2. 🟠 «اقدام بعدی» (پرداخت، ثبت نظر) روی هر سفارش دیده نمی‌شود.
3. 🟡 فیلترها تزئینی‌اند؛ pager جعلی؛ نشان «نوبت ۳ از ۶» برای دوره‌ای نیست.

**جزئیات سفارش**
1. 🔴 فقط یک وضعیت (تخصیص‌یافته) fixture دارد؛ ۹ وضعیت قابل مشاهده نیست؛ `mns_order` نادیده گرفته می‌شود.
2. 🟠 جملهٔ انسانی وضعیت و «قدم بعدی» در هدر نیست؛ StickyActionBar پرداخت نیست.
3. 🟠 لغو سفارش، ثبت نظر، بخش «نتیجهٔ مراجعه» و PriceSummary نیست؛ «همان پرستار» فقط لینک خام به ویزارد.
4. 🟡 دکمهٔ «تماس با پرستار» بدون قاعدهٔ کسب‌وکار (در بریف مشخص نیست بیمار شمارهٔ پرستار را ببیند) → باید با تماس پشتیبانی جایگزین یا TODO شود.

**بیماران من**
1. 🟠 جدول + فرم کنار هم؛ ویرایش/حذف نیست؛ «سفارش برای این فرد» نیست.
2. 🟠 فیلدهای بریف (سن، جنسیت، بیماری زمینه‌ای) در فرم نیست؛ «نسبت» متن آزاد است.
3. 🟡 حالت خالی (فقط خودم) و خطای فرم تعریف نشده.

**فاکتورها**
1. 🔴 لینک‌های «پرداخت» و «دانلود» `href="#"`؛ جزئیات فاکتور و PriceSummary وجود ندارد.
2. 🟠 خلاصهٔ «مبلغ پرداخت‌نشده»، تب‌ها، نشان «اصلاح‌شده + نسخه» و «اعتراض به مبلغ» نیست.
3. 🟠 صفحات بازگشت از درگاه (موفق/ناموفق) نیست.

**خدمات دوره‌ای**
1. 🔴 صفحه یک **فرم ساخت الگو** است؛ طبق بریف الگو در ویزارد ساخته می‌شود و این صفحه باید مدیریت برنامه‌ها باشد.
2. 🟠 کارت برنامه، نوار پیشرفت، نوبت بعدی، هشدار «نوبت بدون پرستار» و فاکتور مکمل نیست.
3. 🟡 تاریخ‌ها ورودی متنی؛ «نوبت‌های نمونه» یک پاراگراف.

**کارت وفاداری**
1. 🟠 تاریخچهٔ مهرها، اثر لغو بر مهر و قواعد (accordion) نیست.
2. 🟡 تخفیف سفارش اول یک خط کوچک پایین صفحه؛ جشن تکمیل کارت نیست.
3. 🟡 ارقام شمارهٔ اسلات مهر لاتین چاپ می‌شود (`(string) $i`).

**پرسشنامه‌ها**
1. 🟠 لیست «در انتظار/ثبت‌شده» نیست؛ فقط یک فرم بی‌زمینه (کدام سفارش؟ کدام پرستار؟).
2. 🟠 ستاره‌ها برچسب سطح ندارند و نقش radiogroup ندارند؛ انتخاب نوع متن (نظر/پیشنهاد/شکایت) نیست.
3. 🟠 ثبت برگشت‌ناپذیر بدون تأیید؛ حالت فقط‌خواندنی و صفحهٔ تشکر نیست؛ ورود مستقیم از لینک پیامک طراحی نشده.

### پنل پرستار

**قالب کلی**
1. 🔴 بدون کنترل لاگین/نقش پرستار.
2. 🟠 bottom nav ندارد (پرستار تقریباً همیشه موبایل است).
3. 🟠 «کیف پول / برداشت» و «پنل مدیار» بدون نشانهٔ external.

**داشبورد**
1. 🟠 هیروی گرادیانت (`linear-gradient`) + ردیف متریک بی‌اقدام (هر دو anti-pattern بریف).
2. 🔴 کلید «پذیرش درخواست» و کارت «کار بعدی» با «شروع خدمت» در داشبورد نیست.
3. 🟠 بخش «نیازمند اقدام» (گزارش ناقص، منتظر پرداخت بیمار) و هشدار «تا ثبت گزارش تسویه نمی‌شود» نیست.
4. 🟡 برنامهٔ امروز به‌صورت جدول (اسکرول افقی موبایل) به‌جای تایم‌لاین.

**سفارش‌های من**
1. 🟠 تب امروز/پیش‌رو/انجام‌شده و فیلتر «نیازمند اقدام» نیست.
2. 🟠 پیام مؤدبانهٔ «پیگیری پرداخت» برای سفارش‌های منتظر پرداخت نیست.
3. 🟡 کارت‌ها خوب‌اند ولی با style درون‌خطی ساخته شده‌اند.

**جزئیات، چک‌لیست و گزارش** (مهم‌ترین صفحه)
1. 🔴 همهٔ بخش‌ها هم‌زمان در یک صفحهٔ بلند؛ جریان مرحله‌ای (آماده‌سازی ← انجام ← چک‌لیست ← دارو ← گزارش) و نشانگر پیشرفت نیست؛ «شروع» و «پایان» هم‌زمان فعال‌اند.
2. 🔴 مرحلهٔ دارو دو شاخه (با/بدون نسخه + پزشک مشاور) ندارد؛ پیامد «عدم تأیید → نیازمند بررسی» نمایش داده نمی‌شود.
3. 🟠 زمان‌سنج سپری‌شده، ذخیرهٔ خودکار و نشانگر «ذخیره شد» نیست؛ کپی آدرس و «باز کردن در مسیریاب» نیست.
4. 🟠 «مورد فوری» با `window.confirm` و جدا از گزارش؛ ثبت نهایی گزارش بدون مرور و تأیید.
5. 🟡 اقلام مصرفی فقط چک‌باکس؛ استپر تعداد نیست.

**برنامه و دسترسی**
1. 🔴 تقویم شمسی واقعی نیست (شبکهٔ میلادی + برچسب ماه شیفت‌خورده؛ روزها و جمعه‌ها غلط‌اند).
2. 🟠 برنامهٔ هفتگی فقط switch + متن ساعت؛ افزودن/حذف بازه و «کپی در روزهای دیگر» نیست.
3. 🟠 سفارش‌ها روی تقویم و هشدار تداخل («در این روز ۲ سفارش دارید») نیست؛ نوار «تغییرات ذخیره‌نشده» نیست.
4. 🟡 فلش‌های ماه گلیف متنی‌اند.

**امتیازهای من**
1. 🟠 «اخلاق / نظم» در یک متریک با دو عدد فشرده؛ نمایش بصری سه دسته نیست.
2. 🟠 تعداد امتیازها و نشان‌ها (کسب‌شده/بعدی) نیست.
3. 🟡 حالت خالی ندارد.

**پروفایل**
1. 🟠 هیروی گرادیانت؛ آپلود آواتار نیست.
2. 🟠 بخش «مشخصات تأییدشده» (قفل) و فیلدهای قابل‌ویرایش (تلفن، بیمارستان) نیست.
3. 🟠 انتخاب چیپی شهر/منطقه نیست (فعلاً متن خواندنی در صفحهٔ برنامه).
4. 🟡 FAQ اولی پیش‌فرض باز است و محتوای مالی را تکرار می‌کند.

### عضویت پرستار

1. 🟠 فرم تک‌صفحه به‌جای ویزارد ۴ بخشی؛ پیش‌نویس و مرور نهایی نیست.
2. 🟠 فیلد پایان خدمت همیشه دیده می‌شود (باید فقط برای «آقا»)؛ کدملی و موبایل در فرم نیست.
3. 🟠 آپلود خام بدون پیش‌نمایش، راهنمای کیفیت و پیام محرمانگی کنار فیلد.
4. 🟠 متن قرارداد (نسخه + تاریخ) نمایش داده نمی‌شود؛ فقط یک چک‌باکس.
5. 🔴 حالت‌ها فقط یک notice هستند: «در انتظار» تایم‌لاین و خلاصه ندارد؛ «ردشده» همان فرم خالی را بدون پیش‌پرکردن و علامت فیلدهای ایرادی نشان می‌دهد.

### ادمین «خدمات پرستاری»

1. 🟡 stub نسخه/اسکیما؛ هیچ شمارندهٔ «نیازمند توجه» و جدول native نیست (طبق بریف، آخرین کار فاز ۶).

## ۶. تصمیم‌ها و فرض‌های پیشنهادی برای فاز ۱

1. **لایهٔ ریست scoped** (`.mns-scope`) جایگزین ۷۹ `!important` پراکنده می‌شود؛ تم `section/aside { display:block }` و استایل input را override می‌کند.
2. **نگاشت رنگ‌های hard-code روی توکن‌ها:** هیچ مقدار تازه اضافه نمی‌شود؛ رنگ‌های «فوری» از `--mns-danger`/`--mns-warn` ساخته می‌شوند.
3. **Mobile-first:** بازنویسی media queryها به `min-width` (۷۶۸، ۱۲۸۰)؛ بدون تغییر ظاهر دسکتاپ فعلی تا صفحه بازطراحی شود.
4. **منبع واحد وضعیت** در PHP (مثلاً `MNS_Order_Status`) تا view و JS هر دو از آن بخوانند؛ fixtureها فقط `status` slug بدهند، نه `tone` و `status_label`.
5. **قرارداد fixture یک‌دست** برای «سفارش»، «بیمار» و «فاکتور» (کلیدهای فعلی حفظ و کلیدهای جدید اضافه می‌شوند تا view فعلی نشکند).
6. **تبدیل شمسی سبک** (الگوریتم استاندارد jalaali در ~۶۰ خط JS و معادل PHP) به‌جای کتابخانهٔ خارجی.
7. **صفحهٔ دموی کامپوننت‌ها** پشت فلگ dev (مثلاً `?mns_page=ui-kit` فقط برای ادمین در حالت static).
8. `// TODO(client-decision)` برای: پذیرش/رد تخصیص (فعلاً قطعی)، قاعدهٔ لغو (`patient_cancel_until`)، انقضای کد تخفیف، نمایش شمارهٔ پرستار به بیمار، نشان‌های امتیاز، تعداد مهر.

## ۷. چیزهایی که خارج از بریف دیدم (فقط پیشنهاد، اجرا نمی‌شود)

- بازنویسی URL تمیز (`/nursing-patient-panel/orders/`) به‌جای query string — `MNS_Rewrite` خالی است.
- هم‌پوشانی هدر Elementor با محتوای پنل در بعضی عرض‌ها مشکل تم است، نه پلاگین؛ فقط `--mns-sticky-top` را با ارتفاع واقعی هدر هماهنگ می‌کنیم.
