# چرخهٔ عمر سفارش و ماشین وضعیت

## وضعیت‌های داخلی (کد: `MNS_Order_Status`)

| کلید | برچسب | tone | تب بیمار |
|---|---|---|---|
| `submitted` | ثبت‌شده | neutral | active |
| `assigned` | تخصیص‌یافته | success | active |
| `in_progress` | در حال انجام | primary | active |
| `medication` | مرحلهٔ دارو | primary | active |
| `service_ended` | پایان خدمت | warning | active |
| `invoiced` | فاکتور صادر شده | warning | unpaid |
| `paid` | پرداخت‌شده | success | done |
| `completed` | تکمیل‌شده | success | done |
| `cancelled` | لغوشده | muted | cancelled |
| `needs_review` | نیازمند بررسی | danger | active |

- `is_cancelable()` فقط `submitted`/`assigned`. `stages()`: ثبت، پرستار، خدمت، پرداخت، تکمیل.
- تب‌های سفارش بیمار: همه / فعال / منتظر پرداخت / تکمیل‌شده / لغوشده. `PER_PAGE=10`.
- وضعیت‌های فاکتور: `unpaid` پرداخت‌نشده، `dispute` اعتراض در حال بررسی، `paid` پرداخت‌شده. انواع: `normal` (و در کد قدیمی `prepay`، `supplement` — منتفی شده، بنگر `inconsistencies.md`). تب‌ها: all/unpaid/paid.

## تغییرات نسبت به کد فعلی (از چت)

- **«نیازمند بررسی» علامت (flag) است نه فقط وضعیت** در چند حالت: عدم تأیید پزشک، نتیجهٔ ناقص/انجام‌نشده — وضعیت اصلی را عوض نمی‌کند (پرستار هنوز می‌تواند پایان/مراحل را ثبت کند) ولی **صدور فاکتور را مسدود می‌کند** تا ادمین علامت را بردارد. در حالت «پایان روز بدون شروع» و «خطای صدور فاکتور» وضعیت واقعاً `needs_review` می‌شود.
- مرحلهٔ دارو از لحظهٔ شروع خدمت باز می‌شود (پیش‌نویس + ثبت مشاوره)؛ ثبت نهایی فقط بعد از پایان.
- زیر‌وضعیت‌های مراحل بعد از پایان: چک‌لیست / دارو / گزارش هرکدام: شروع‌نشده → پیش‌نویس → ثبت‌شده (قفل) → «برای اصلاح باز شده».

## جریان اصلی

```
ثبت سفارش (بیمار یا ادمین)
  └ A-13 بررسی دسترسی پرستار (هم‌زمان با ثبت)؛ نبودن → سفارش ثبت نمی‌شود
  └ A-14 ایجاد سفارش + تخصیص (خودکار یا لیست «بدون پرستار» برای ادمین)
submitted ──(تخصیص)──► assigned
  ├─(بیمار/ادمین لغو، تا قبل از شروع)──► cancelled
  └─(پرستار «شروع خدمت»، در پنجره مجاز)──► in_progress       [بیمار دیگر نمی‌تواند لغو کند]
        ├ چک‌لیست/دارو: پیش‌نویس + (مشاوره حین خدمت)
        └─(پرستار «پایان خدمت»)──► service_ended
              ├ ثبت نهایی چک‌لیست  (+ مرحله دارو اگر لازم) + گزارش پایان مراجعه
              └─(همهٔ مراحل لازم ثبت نهایی و بدون علامت بررسی)──► [صدور خودکار فاکتور] ──► invoiced
                    ├ اعتراض بیمار ──► dispute (پرداخت قفل) ──► ادمین ویرایش نسخه‌دار ──► invoiced (نسخهٔ جدید)
                    └ پرداخت موفق (verify سمت سرور) ──► paid ──► completed
                           └ شارژ کیف پول پرستار (۹۰٪، یک‌بار) + مهر وفاداری + پرسشنامه
```

- **مهر وفاداری** با «پایان خدمت» ثبت می‌شود (تصمیم کاربر)، نه با پرداخت.
- **پرسشنامه** با پایان خدمت پیامک می‌شود (لینک یک‌بارمصرف نیست).
- اگر بدون ثبت گزارش: سفارش `completed` نمی‌شود و سهم پرستار شارژ نمی‌شود.

## شرایط استثنا

| وضعیت | شرط | اثر |
|---|---|---|
| روز خدمت تمام شد و شروع نشد | cron | → `needs_review` (ادمین در رصد؛ پرستار: «با پشتیبانی تماس بگیرید»؛ هیچ شاخص تأخیر ساخته نمی‌شود) |
| عدم تأیید پزشک (مرحلهٔ دارو) | ثبت مشاوره | علامت «نیازمند بررسی» + پیامک فوری ادمین؛ همهٔ داروها «تجویز نشد» |
| گزارش «ناقص/انجام نشد» | ثبت نهایی گزارش | علامت بررسی؛ فاکتور تا بررسی ادمین صادر نمی‌شود؛ تمبر بر می‌گردد (اگر «انجام نشد») |
| اطلاع فوری | کلید در گزارش | پیامک ادمین‌ها؛ سفارش بالای رصد؛ وضعیت را عوض نمی‌کند |
| خطای صدور خودکار فاکتور | سرور | `needs_review` + اعلان ادمین |
| پرستار عوض شد (ادمین) | تخصیص دستی | پرستار قبلی: «این سفارش دیگر به شما اختصاص ندارد» (بدون داده)؛ اگر شروع شده، انتقال ممکن نیست تا ادمین وضعیت را برگرداند |
| ادمین برگرداندن شروع/پایان | با دلیل + لاگ | اعلان داشبورد پرستار |
| باز شدن قفل چک‌لیست/دارو | فقط تا قبل پرداخت | فاکتور قفل، ثبت دوباره → نسخهٔ جدید + سهم جدید |

## قواعد هم‌زمانی (اتمیک)

- لغو: `UPDATE … SET status='cancelled' WHERE id=? AND status IN ('submitted','assigned')`.
- شروع: `UPDATE … WHERE status='assigned'` + بررسی پنجرهٔ مجاز سمت سرور؛ اگر هم‌زمان لغو/تغییر پرستار → رد با پیام روشن.
- پایان: `WHERE status='in_progress'`؛ ذخیرهٔ `duration_minutes`.
- صدور فاکتور: یک‌بار برای هر نسخهٔ چک‌لیست (قفل/کلید یکتا).
- پرداخت و بازگشایی قفل هم‌زمان: **پرداخت برنده** و بازگشایی لغو می‌شود.
- تخصیص، شمارش ظرفیت بازه و ثبت مرخصی: قفل ردیف پرستار یا یک تراکنش.
- قبل از تلاش مجدد پس از خطای شبکه، وضعیت را از سرور بخوان.

## نگاشت وضعیت داخلی به زبان بیمار

| داخلی | بیمار |
|---|---|
| ثبت‌شده | «در حال تعیین پرستار» |
| تخصیص‌یافته | «پرستار تعیین شد» |
| در حال انجام | «در حال انجام» (سبز) |
| پایان خدمت / ناتمام | «خدمت انجام شد» |
| فاکتور صادر شده | «در انتظار پرداخت» (نارنجی) |
| اعتراض | «اعتراض در حال بررسی» |
| پرداخت‌شده/تکمیل | «تکمیل‌شده» (سبز) |
| نیازمند بررسی | «در حال بررسی توسط پشتیبانی» (علت داخلی نمایش داده نشود) |
| لغوشده | «لغو شد» (توسط شما / توسط پشتیبانی) |

> نگاشت **فقط سمت سرور** انجام شود.
