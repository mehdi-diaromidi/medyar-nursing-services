# قوانین کاری و ترجیحات کاربر

## قانون Cursor (`.cursor/rules/document-patches-after-update.mdc`)

هر تغییری در پلاگین/قالب ثالث (یا هر کدی که با آپدیت پاک می‌شود) باید در **همان نوبت** در `docs/` مستند شود:

- پچ قالب → `docs/THEME-PATCHES-AFTER-UPDATE.md`
- پچ چندپلاگینی → `docs/MEDYAR-REAPPLY-PATCHES-AFTER-UPDATE.md`
- پیامک/مالکیت رزرو → `docs/MEDYAR-SMS-BOOKING-AND-OWNERSHIP.md`
- مورد جدید → `docs/<NAME>-PATCHES-AFTER-UPDATE.md` + لینک از ایندکس
- هر مدخل: مسیر هدف، تغییر دقیق (قبل/بعد)، دلیل، روش اعمال مجدد (نشانگر/نام متد/هوک).
- ترجیح: child theme / mu-plugin / پلاگین سفارشی به‌جای پچ مستقیم.

## Skillها

### wordpress-dev
پاسخ فارسی، کد انگلیسی؛ بی‌مقدمه و بدون خلاصهٔ اضافه؛ فقط کد تغییرکرده با مسیر. API و هوک‌های هسته؛ **هرگز ویرایش core/ثالث**. امنیت: `wp_unslash`→sanitize، escape دیرهنگام، nonce، `current_user_can`، `$wpdb->prepare`، `permission_callback`، `defined('ABSPATH') || exit;`. پیشوند همه‌چیز. enqueue درست و فقط جای لازم. بدون کوئری در حلقه؛ cache با transient. i18n و RTL. ووکامرس فقط با CRUD/هوک. تغییر حداقلی، بدون ری‌فکتور نامرتبط. عملیات مخرب فقط با تأیید صریح.

### ftp-auto
بنگر `deploy-and-verify.md`.

### from-screen-ux
«دقیقاً همان طرح، نه تفسیر یا بهبود». هر المان طرح باشد، المان اضافه نباشد. متن حرف‌به‌حرف با ارقام فارسی. آیکون SVG درون‌خطی (خط ~1.7–1.8، سرگرد، شبکه 24). دسکتاپ 1440 (PNG با ضریب 1.5)، موبایل 390. شکست جدول→کارت در «سفارش‌های من» ≈900px. رفتارها: ویزارد ۴مرحله‌ای، بررسی دسترسی AJAX سه‌حالته (سبز/زرد/قرمز)، تب/فیلتر/جستجو، لغو با تأیید + عملیات اتمیک، منوی ⋯، حالت‌های خالی. بک‌اند ناموجود → mock + TODO. حلقهٔ تأیید تا صفر اختلاف؛ فیلد ≥16px، هدف لمسی ≥44px، بدون اسکرول افقی، کنسول بدون خطا. روی FTP: بکاپ قبل از تغییر، هیچ فایلی حذف نشود.
- توکن‌های داخل skill (`#0a6cb6` و …) **جایگزین شده‌اند** با توکن‌های سایت؛ رنگ اصلی **`#0272b1`**.

### ui0ux / ui-ux (یکسان)
نقش Principal Product Designer؛ شبکهٔ 8pt؛ بدنه ≥16px موبایل؛ کنتراست ≥4.5:1؛ WCAG 2.2 AA؛ همهٔ حالت‌ها (خالی، بارگذاری، جزئی، خطا، موفق، آفلاین، اولین استفاده، سرریز)؛ لمس 44px؛ حرکت 100–400ms با `prefers-reduced-motion`.

## ترجیحات صریح کاربر

**روند**
- اول UI استاتیک با داده نمونه، بعد بک‌اند.
- استقرار و تأیید خودکار بدون اجازه گرفتن («تا ته برو بدون تایید»)؛ برای ریزتغییرات ظاهری گاهی «بدون تست انجام بده».
- قبل از پیشروی از اعمال واقعی تغییر مطمئن شو.
- سرعت مهم است.
- گرافیک/تصویر خودت نساز؛ placeholder هم‌اندازه بگذار.
- **در گزارش‌ها/اسناد: زمان‌بندی، ددلاین و برآورد هزینه نیاور** («فقط جزئیات پروژه و بریف دقیق»).
- در طراحی صفحه‌ها: **هدر، فوتر و منوی سایت را نگو** (قالب می‌دهد)؛ فقط محتوای داخل صفحه.
- خروجی طراحی هر صفحه: اصل طراحی، ساختار بالا به پایین، هر بلوک، حالت‌های خالی/خطا، موبایل/دسکتاپ، نکات پیاده‌سازی، **موارد باز**؛ بعد از جواب کاربر «مجدد کل متن را تولید کن».

**ظاهر**
- مرجع UX = **ARP**: پوستهٔ پنل، سایدبار، هدر صفحه (`arp-refs__head`)، هدر کارت (`arp-card__head`)، دکمهٔ outline (`arp-btn-outline`)، فیلتر (`arp-refs-filters`)، جدول (`arp-table`)، صفحه‌بندی (`arp-refs-pager`).
- توکن‌ها (فونت، رنگ، شعاع، سایه، فاصله) را عوض نکن؛ رنگ اصلی `#0272b1`.
- RTL، تاریخ شمسی، ارقام فارسی، «تومان».
- پوستهٔ پنل حفظ شود: سایدبار دسکتاپ / drawer موبایل / bottom-nav.
- طرح PNG قانون است؛ اگر PNG ناوبری/فونت ندارد، از داشبورد/ARP پیروی کن. ناوبری همهٔ صفحات پنل دقیقاً مثل داشبورد.

**سفارش‌ها/فاکتورها**
- فیلتر «بر اساس بیمار» **حذف** (سفارش‌ها و فاکتورها).
- کد سفارش فقط **۵ رقم** (`MD-48215`).
- ردیف دسکتاپ: همهٔ اطلاعات در **یک خط**.
- چیپ «دوره‌ای · نوبت…» نه؛ **تاریخ** نشان بده.
- سوابق: جعبهٔ جدا با **جدول + صفحه‌بندی ARP** (نه «نمایش بیشتر»).
- فیلترهای ARP زیر نوار جستجو با منطق JS خود ARP.
- موبایل: padding افقی روی `#mns-main` مثل ARP.

**ثبت سفارش**
- گزینهٔ «فرقی ندارد» برای جنسیت **اضافه نشود** تا کارفرما تصمیم بگیرد.
- شمارهٔ پرستار به بیمار نشان داده نشود؛ هماهنگی از طریق پشتیبانی.
