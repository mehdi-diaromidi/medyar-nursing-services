> **هدف این پوشه:** درک کامل و جزئی از پروژه + مسیر مشخص ساخت (بک‌اند، دیتابیس، منطق) تا **ایجنت سازنده (Cursor)** بدون حدس‌زدن کار کند و **ناظر (Claude)** بتواند هر تحویل را با معیارهای روشن بررسی کند.
> تاریخ: ۱۶ نوامبر ۲۰۲۶ · پیش‌نیاز: [`../PROJECT-LOGIC.md`](../PROJECT-LOGIC.md).
> **این پوشه فقط سند است؛ هیچ کدی ساخته نشده.** رمز/کلید/FTP هرگز در این اسناد نیاید.

## قراردادهای شناسه
- **R-xxx** قاعدهٔ کسب‌وکار (در `03`)؛ **E-xxx** موجودیت/جدول (در `02`)؛ **API-xxx** endpoint (در `04`)؛ **S-xxx** تنظیم (در `06`)؛ **M-n** milestone؛ **T-n.m** کارت وظیفه؛ **AC-xxx** سناریوی پذیرش (در `10`).
- هر کد/کامنت/commit باید به شناسه ارجاع دهد: مثلاً `// R-ASG-3` یا commit «T-3.2: assignment (R-ASG-1..5)».
- برچسب‌ها: **[قطعی]** تصمیم مالک · **[فرض]** پیشنهاد ما، تا تأیید مالک · **[باز]** نیازمند پاسخ.

## اصل راهبردی (چرا این ترتیب)
۱) فرانت استاتیک و UI نهایی‌شدهٔ بیشتر صفحات **از قبل قرارداد داده را تعیین کرده** (شکل fixtureها = شکل پاسخ سرور) ⇒ بک‌اند باید همان شکل‌ها را تولید کند و fixtureها **یک‌جا** جایگزین شوند (تصمیم مالک).
۲) چون PHP روی ماشین نیست و هر تست روی develop با FTP انجام می‌شود، **ایمنی بارگذاری و ابزار self-test داخل پلاگین** بخشی از M0 است (بنگر `07-roadmap.md`).
۳) محصول هنوز در چند نقطه [باز] است (فهرست خدمات، قیمت‌ها، متن قرارداد، پترن‌ها)؛ ساختار داده طوری طراحی شده که این‌ها **بدون تغییر schema** بعداً تعیین شوند (JSON ساخت‌نیافته + تنظیمات).
