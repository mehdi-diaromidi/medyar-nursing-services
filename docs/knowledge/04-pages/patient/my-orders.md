# سفارش‌های من — P-44

وضعیت: **طراحی ✔ · استاتیک ✔** (`class-mns-patient-orders.php`، `page-orders.php`، partialها `order-row|order-actions|order-cells|order-table-row|orders-pager`). PNG: `desgin/png/سفارش های من/`. چک‌لیست پیکسلی: `docs/ui-checklist-my-orders.md`.

## ساختار
عنوان «سفارش‌های من» + تعداد + «ثبت درخواست جدید» → ~~فیلتر بیمار (حذف شد)~~ → تب‌ها با شمارنده → جستجو + «فیلتر بیشتر» → لیست → (فعال) کارت/ردیف، (سوابق) جدول ARP + صفحه‌بندی ARP (نه «نمایش بیشتر» — تصمیم UI).

### تب‌ها
| تب | وضعیت‌ها |
|---|---|
| همه | گروه‌ها: «نیازمند اقدام» (پرداخت‌نشده‌ها، بالا) · «فعال» · «سوابق» |
| فعال | ثبت‌شده، تخصیص‌یافته، در حال انجام، پایان خدمت/دارو، نیازمند بررسی (مرتب بر زمان مراجعه) |

### جستجو و فیلتر
جستجو با کد پیگیری یا نام خدمت (ارقام فارسی/عربی → لاتین سمت سرور). فیلتر: بازهٔ تاریخ شمسی، نوع خدمت، «فقط دوره‌ای». چیپ فیلتر فعال قابل حذف + «پاک‌کردن همه». state در query string. فیلترهای ARP زیر نوار جستجو با منطق JS خود ARP.
پارامترها: `q, from, to, service, recurring, type, sort, order, mns_p, mns_tab`.

### کارت موبایل (۵ ردیف)
۱) نام خدمت + چیپ وضعیت (متن+رنگ) · ۲) چیپ بیمار (برای دوره‌ای «دوره‌ای · نوبت ۳ از ۶» — **در دسکتاپ به‌جای آن تاریخ نشان بده**) · ۳) تاریخ/بازه (نسبی برای نزدیک) · ۴) آواتار/نام پرستار (بعد از تخصیص) · ۵) کد پیگیری+کپی و مبلغ (فقط بعد از صدور فاکتور؛ قبل: «پس از خدمت محاسبه می‌شود»). پایین: دکمهٔ اصلی + منوی ⋯. شکست جدول→کارت ≈ 900px (container query `mns-olist` ≥ 740px). **کد ۵ رقمی `MD-48215`**؛ ردیف دسکتاپ یک خط.

### لغو
فقط قبل از «در حال انجام». دیالوگ «سفارش لغو شود؟» + دلیل اختیاری (فقط مدیریت) + «بله، لغو شود»/«انصراف». `UPDATE … WHERE status IN ('submitted','assigned')` اتمیک. اگر پرستار شروع کرده: «پرستار خدمت را شروع کرده، برای لغو با پشتیبانی تماس بگیرید» (بدون صفحهٔ خطا). بعد: زمان پرستار آزاد، پیامک به پرستار و ادمین‌ها، تأیید به بیمار. بدون مبلغ/مهر.

### «همان پرستار»
بررسی دسترسی و جنسیت؛ ناموجود → «این پرستار در این زمان آزاد نیست» + «ادامه با انتخاب خودکار».

### حالت‌ها
خالی: «ثبت اولین درخواست» + ۶ دسته (+بنر تخفیف اول)؛ فیلتر بی‌نتیجه: «سفارشی با این فیلتر پیدا نشد» + «پاک‌کردن فیلتر»؛ تب خالی: پیام مثبت («فاکتور پرداخت‌نشده‌ای ندارید»)؛ skeleton؛ خطا «بارگذاری نشد» + تلاش دوباره (فیلتر حفظ).

## رفتار
بعد از پرداخت: بازگشت به همین لیست، تب مناسب، پیام «پرداخت ثبت شد». سفارش تلفنی ادمین بعد از OTP همان شماره دیده می‌شود. دوره‌ای کنار بقیه.
